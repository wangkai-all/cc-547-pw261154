# 产线双相机帧配对演示

纯 Node.js 内置模块实现（无第三方依赖）：两台本地相机各自上报「照片编号 + 触发计数」，
工位控制源独立上报产品通过信号；接收端保留未配对件，组装端按触发周期关联，
质检端只处理「成对且属于同一产品」的样本。

## 运行

```bash
node server.js          # 读取 PORT 环境变量，默认 3000，绑定 127.0.0.1
PORT=3100 node server.js
```

打开 `http://127.0.0.1:3000/`，页面提供三个操作（结果全部由引擎实际处理得出，
业务结果区带 `data-evidence-result` 属性，便于核对操作前后内容）：

| 按钮 | 对应接口 | 内容 |
| --- | --- | --- |
| 接收双相机帧 | `POST /api/demo/batch1` | 正常配对 + 丢帧漏配 + 重复帧 + 乱序帧，末尾留一件悬置未配对帧 |
| 模拟复位后续收 | `POST /api/demo/batch2` | 相机A重新计数（12→1）后继续上报，批次关闭结算 |
| 查看质检配对 | `GET /api/state` | 质检接收 / 隔离 / 拒收与接收端保留的未配对件 |

页面还可调整错配 / 漏配代价与等待窗（`POST /api/config`），
代价决定策略后自动清空数据，便于对比两种策略下复位场景的不同结局。

## 测试

```bash
node --test
```

覆盖：正常配对、乱序容忍、过站信号晚到补判、漏配（等待窗耗尽）、重复帧、
无过站信号、复位后旧图不接新件、跨产品配对隔离、策略代价选择、
合成数据两批次全流程（固定窗 / 动态校正）、HTTP 接口与页面标记。

## 设计要点

### 固定等待窗 vs 动态校正（由错配、漏配代价决定）

- **固定等待窗**（`fixed-window`）：只接受两侧触发计数完全一致的配对，
  伴侣帧在等待窗（对侧帧数）内不到即判漏配。绝不强行配对 → 错配代价高时选用。
- **动态校正**（`dynamic-correction`）：从「对侧最新帧仍滞留未配对」的相邻帧
  学习两侧计数偏移（滑动窗取中位数），按偏移继续配对。
  漏配代价高时选用；校正可能错配，由质检的同产品核对拦截（隔离）。
- `chooseStrategy(costMismatch, costMiss)`：错配代价 ≥ 漏配代价 → 固定窗，否则动态校正。

### 相机重新计数（复位）——旧图不接新件

- 计数回退超出乱序容忍窗（默认 2）即判定复位：该相机代数 +1，
  **立即清空两侧全部未配对缓存**（按漏配记录），偏移估计重新学习。
- 因此复位前滞留的旧图（如 B-0013）绝不会与复位后同计数的新件配成对。
- 复位后两种策略的分野：固定窗下两侧计数不再相等 → 全部漏配（安全但停产）；
  动态校正学到新偏移（如 13）恢复配对，但质检按原始计数独立核对过站记录，
  发现两帧分属不同产品（P001 ≠ P014）→ 全部隔离，不会错挂到新件的产品档案上。

### 质检规则

- 样本成对后，对每帧用其自身触发计数独立查工位过站记录（不轻信组装端关联）：
  两帧指向同一产品 → 接收；分属不同产品 → 隔离（质检不处理）；
  过站信号未到 → 等待，批次关闭仍无信号 → `no-product` 拒收。

## 目录

```
server.js            HTTP 服务（内置 http 模块，PORT / 127.0.0.1）
lib/engine.js        配对引擎（接收端 / 组装端 / 质检端、复位保护、策略选择）
lib/scenario.js      合成数据（可复现正常、漏配、重复、乱序、复位各情况）
public/              演示页面（data-evidence-result 业务结果区）
test/                node --test 用例（正常 + 异常）
```
